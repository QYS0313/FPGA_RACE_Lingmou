2026-10-30：工程一 D1 / A8，帧差运动区域检测
  下载文件仍为 bits/demo_video.bit；工程二 D2/E7 的绿色光点追踪和形状描边未改动。
  上一版备份：backups/before_video_a8_motion_20261030（含源码、上位机、测试和 A7 位流）。

  使用：
    1. 下载 A8 后重新打开 tools/demo_gui.cmd（项目根 tools 目录的启动入口），连接 COM5。
    2. 在“视频 / 手动云台”页选择“帧差运动检测”，HDMI 显示 MODE 5 MOTION。
    3. 固定云台，让手或物体在画面中移动；青色框显示运动区域，最多3个。
       OSD 第二行显示 MOTION COUNT；X/Y/W/H 为本次最大运动区域的中心和宽高，单位像素。
       这里显示的是发生变化的区域，不是物体类别或静止物体的完整轮廓。
    4. 默认差分阈值18、最小区域3块。一块是20×20原图像素范围。
       噪点多时提高阈值或最小块数；小目标漏检时逐步降低，两项不要同时大改。
       修改后点“应用参数”，界面显示读回值，并自动重建参考帧。
    5. 可沿用“基础算法范围”的全屏或选定矩形；建议初次测试使用全屏。
       目标检测框作为选区来源时，沿用已有颜色目标框；四边形仍用于原附加特效。
    6. 云台回位、速度移动或停车过渡时暂停；停下等待12个输出帧，再建立新参考帧。
       外力挪动摄像头不在自动暂停范围内，挪动后可点“重建参考帧”。
    7. 停止移动后框短暂保持，随后消失，属于帧差检测的正常行为。
       切换回原图/灰度/颜色跟踪即可退出；本功能不启动电机或激光。

  实现与显示含义：
    1280×720原始检测RGB，每5×5位置取4×4平均，形成256×144的8-bit灰度参考图。
    对新的摄像头时间戳做前后帧绝对差；HDMI重复帧不更新参考图、不清空检测结果。
    4×4低分辨率样点中至少4点超过阈值，才成为有效运动块；合并邻近区域，过滤小块。
    最多3组区域累积，最多跨越两个空块合并运动边缘；不是无限数量连通域分割。
    相邻物体可能合成一个框；超过3个或极零散的变化不保证逐个完整显示。
    单帧超过选区25%的样点变化时抑制该帧，防止光照突变/画面大幅移动误报；
    很大的快速运动物体也可能触发此抑制，建议初测使用全屏和占画面较小的物体。
    连续2个新帧检出才显示；短暂缺失保持6个新帧。无新时间戳约2秒后清除旧结果。
    上位机“变化采样点”是超阈值的低分辨率灰度点数，不是物体面积，不乘25冒充精确像素面积。
    缺少帧时间戳、不完整帧、手动云台运动都会丢弃参考并重新建立，避免旧图产生错误框。
    FPS +15 和 DLY 平滑后 -50ms 的显示规则保持 A7；实际计数和测量不变。

  协议（仅 D1/A8）：
    0x11=5：帧差模式；0x76 写阈值(1..255)，0x77 写最小块数(1..32)。
    0x78/0x79 读参数；0x7B 重建参考；0x7C 返回能力标识 D8。
    0x7A 按data=0,1,2,3读取一致快照，0锁存：flags,count,changed_cells低字节/高字节。
    flags bit0有效、bit1建参考、bit2云台暂停、bit3全局变化抑制。
    原0x59统计记录和目标坐标命令保留；在模式5时返回最大运动区域的坐标。
    参数为运行时参数，重启恢复18/3。

2026-10-28：工程一 D1 / A5，真实帧龄/处理延迟叠加
  原 OUT 的位置改为 DLY xxxxMS，单位毫秒；不再在 HDMI 上显示 OUT。
  FPS 保持之前的显示规则（实测采集 FPS +15）；DLY 不加任何人为偏移。
  测量起点：FPGA RAW 图像入口 S_axis_tuser 帧开始。
  测量终点：该图像从 DDR 读出，经视频算法后首个有效像素进入 OSD 前。
  不包含摄像头曝光/内部缓存、HDMI 线后显示器内部处理与面板响应时间。
  精度约 1 ms（毫秒量化和时钟域同步边界），不声称亚毫秒精度。
  OSD 在帧边界锁存已完成测量，所以显示的是上一输出帧的首像素帧龄。
  采集时间戳保存在 4×32-bit DDR 字中的 4 个空闲高字节，RGB888 字节不变。
  时间戳随数据经过 FIFO 和 DDR，不通过“最近摄像头帧”或读写指针猜测对应关系。
  相机帧被 HDMI 重复显示时，其 DLY 会增长；这属于该输出帧的真实帧龄。
  无有效时间戳、首字 FIFO 为空或帧龄超出 4095 ms 时显示 ----MS。
  时间戳是 24-bit 毫秒模计数（约4.66小时回绕），正常短间隔经过回绕仍可测量。
  串口原有 camera_fps / display_fps / 帧计数记录格式不变；本轮 DLY 仅加到 HDMI。

    建议放在工程一，作为独立视频演示模式；复用原摄像头、DDR 和 OSD。
    起步规格：160×90 灰度，保存上一帧，绝对差分 + 可调阈值 + 简单去噪，
              一个运动区域的框和面积统计，坐标放大回 1280×720。
    上一帧存储 14400 byte，按常见 2K×8 映射约8块 ERAM；连同辅助缓冲预留8～10块。
    预计额外约300～800 Slice、0 DSP；这是方案预算，不是综合测量。
    320×180 的8-bit上一帧需要57600 byte，按相同映射约29块 ERAM，工程一余量过紧，
    不建议第一版就使用该规格。全分辨率需要921600 byte，需专门设计 DDR 访问。
    工程二 RAM 更多，但逻辑/DSP余量更少，且后续还需留给形状/轮廓算法。
    两工程只要云台转动，帧差都会把背景移动判为运动；建议第一版固定云台检测，
    手动转动期间暂停检测，停止并重新建立参考帧后再恢复。
    必须按新的摄像头帧更新时间戳/参考图，不能把 HDMI 的重复帧当作新采样帧，
    否则会产生“有运动—无运动”交替闪烁。

3. 固定零位与范围
  下轴逻辑零位：编码器约 116.924°（raw 21285）。
  上轴逻辑零位：编码器 180°（raw 32768）。
  回位过程不使用工作限位，两轴同时返回；回位成功后下轴 ±60°，上轴 150°～300°。
  正方向：下轴左转，上轴抬头。
  手动速度默认 2 rpm，可调 0.2～10 rpm；有加减速及限位前减速。
  不写入电机内部 PID、电流上限、编码器零点。
  手动速度指令失去主机心跳约 500 ms 后，FPGA 请求零速，等停稳后保持；反馈故障则尝试失能。
  上轴重心偏移，失能时需承托；不要把“停止并保持”与“失能”混淆。
  正在回位时点击停止或按 Esc，会中断回位并请求双轴失能；正常手动/跟踪过程的停止则减速保持。

  操作示例：
    a. 点“灰度”，将“基础算法”范围选为“选定区域”。
    b. 来源选“手动矩形”，输入坐标，点击“应用并读回”。区域内灰度，区域外保留上一级彩色图。
    c. 点“仅轮廓”、特效范围仍选“选定区域”，可在该矩形周围显示白边。
    d. 勾选“亮度直方图均衡”，分别尝试全屏和选区，点击“应用并读回”对比。
    e. 改用“目标检测框”，选目标颜色；检测到目标后可勾选锁定，再应用，移开目标检查区域保持。
  基础算法/特效单选项点击即发送；高级开关、三组范围、坐标和检测框选项统一点击“应用并读回”。
  设置整体按帧切换，直方图需要完整统计一帧后才产生新映射；白平衡恢复时沿用原有渐变更新。
  长参数读写在手动移动/回位时被拒绝，先松键停稳再操作。界面新增滚动条，Esc 仍可停止。
  本版设置保存在 FPGA 运行寄存器，重新下载/重新配置/断电后恢复上述默认值；不是 Flash 持久化设置。
  开关是运行时效果旁路，不释放已综合的资源；新增算法的实际资源以当前 video_build.txt 为准。

  D1 扩展协议：0x74 返回 C1；0x70 选择暂存字节 0～9，0x71 写字节，0x72/A5 整组提交。
  0x73 按 DATA 索引读已提交字节；0x75 bit0 为跨时钟传递忙。
  提交返回 0 成功、1 忙、2 越界/保留位错误、3 提交键错误。
  数据布局：flags、scopes、X0/Y0/X1/Y1（小端 uint16）。flags bits 0～5 对应上述六个开关；
  scopes bits 0/1/2 为基础/特效/均衡的选区使能，bit3 为检测框来源。
  已提交读回指源配置被接受，图像在随后帧间生效；不表示已写入 Flash。
